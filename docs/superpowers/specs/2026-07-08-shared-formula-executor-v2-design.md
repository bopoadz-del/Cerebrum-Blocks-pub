# Design: Generalize `formula_executor_v2` as a shared deterministic reasoning block

## Goal

Move `formula_executor_v2` from a construction-only block to a **shared, domain-agnostic reasoning/calculation block** available in every domain kit.

## Scope

- `app/blocks/formula_executor_v2.py` — domain-agnostic description and tags.
- `app/prompts/codegen_system.py` — align allowed imports with sandbox policy (`numpy`, `sympy`, `pint`), remove construction-only framing.
- `block_registry/formula_executor_v2/block.json` — shared description.
- `block_store/kits/*/manifest.json` + bundles — add `formula_executor_v2` block and required shared files to every real domain kit.
- `scripts/publish_kit.py` — update generator so future kit publishes include the shared block.
- `block_store/shelves/source_packs.json` — add `formula_executor_v2` as an optional reasoning block for every domain.
- Tests — prompt policy tests, NumPy/SymPy/Pint sandbox tests, SciPy rejection test, kit/source-pack exposure tests.

## Out of scope

- Sandbox allowlist changes beyond what is already whitelisted (`numpy`, `sympy`, `pint` are already allowed).
- Provider/model config.
- Deployment.
- <private-repo>, The_Fork, Fork2.

## Design decisions

1. **Prompt-sandbox alignment.** The codegen prompt currently lists only `math`, `statistics`, `datetime`, `json`, `app.lib.pm_computations`, `app.schemas.cpm`. The sandbox already allows `numpy`, `sympy`, `pint`. The prompt will be updated to match, and a note will explicitly call out that `scipy` is not allowed.
2. **Construction helpers remain allowed but not dominant.** `app.lib.pm_computations` and `app.schemas.cpm` stay in the prompt as optional construction/project-management helpers, not as the block’s identity.
3. **Kit manifests.** Non-construction domain kits are generated by `scripts/publish_kit.py`. The generator will be updated to include `formula_executor_v2` in `blocks`, `core_modules`, and `artifacts` (via shared files). The existing construction manifest is maintained manually and will be edited directly.
4. **Bundles.** Because bundles are generated by `publish_kit.py`, they will be regenerated, not hand-edited.
5. **Source packs.** `formula_executor_v2` is appended to each domain pack’s `blocks` list as a general optional reasoning block. Domain `_v2` blocks remain primary.
6. **Virgin shelf untouched.** Virgin editions stay minimal (`pdf`, `ocr`, `chat`, `image`, `<domain>_v2`); no `formula_executor_v2` there.

## Test plan

- `tests/test_formula_executor_v2.py` (new):
  - `build_codegen_prompt` includes `numpy`, `sympy`, `pint`.
  - `build_codegen_prompt` says `scipy` is not allowed.
  - Prompt no longer frames the block as construction-only.
  - Mocked `FormulaExecutorV2Block` runs NumPy, SymPy, and Pint snippets successfully.
  - `run_sandboxed("import scipy")` fails with a blocked-import message.
- `tests/core/test_kit_manifests.py` (update):
  - Every non-construction domain manifest exposes `formula_executor_v2`.
  - Construction manifest still exposes it.
- `tests/core/test_source_pack_loader.py` (update):
  - Every source pack lists `formula_executor_v2`.

## Risks

- `pint` availability in CI is confirmed in the local venv.
- Regenerating bundles touches many files; the diff will be large but mechanical.
